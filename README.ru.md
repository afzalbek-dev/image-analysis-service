# Image Analysis Service

Готовый к промышленной эксплуатации, высокопроизводительный сервис анализа изображений и перцептивной дедупликации, написанный на Go (Golang). Обеспечивает быструю обработку изображений, извлечение структурных метаданных, кластеризацию цветовой палитры, диагностику резкости и размытия, вычисление перцептивных отпечатков (aHash, dHash, pHash), поиск дубликатов и трансформацию изображений через современный RESTful HTTP API.

---

## Целевая аудитория и назначение

- **Целевые пользователи**: Разработчики бэкенда, медиаплатформы, системы электронной коммерции, DAM-системы (Digital Asset Management) и пайплайны модерации контента.
- **Основная цель**: Предоставить сверхбыстрый и легковесный микросервис на Go для обработки загружаемых изображений, выявления визуальных дубликатов, оценки качества фотографий, анализа цветовой гаммы и трансформации изображений без использования тяжелых внешних зависимостей на C++ или Python.

---

## Ключевые возможности

1. **Извлечение структурных метаданных**:
   - Ширина, высота, соотношение сторон, мегапиксели, цветовая модель (RGBA, Gray, YCbCr, CMYK) и размер файла в байтах.
2. **Анализ цветовой палитры и освещенности**:
   - Кластеризация доминирующих цветов с представлением Hex/RGB и процентом покрытия.
   - Вычисление средней воспринимаемой яркости (от 0.0 до 1.0).
   - Расчет коэффициента динамического контраста.
   - Определение монохромных и черно-белых изображений.
3. **Оценка качества и детектирование размытия**:
   - Оценка дисперсии дискретного оператора Лапласа для определения четкости границ.
   - Автоматическая маркировка смазанных фото (`is_blurry: true/false`).
   - Классификация экспозиции (`under_exposed` — недоэкспонировано, `well_balanced` — сбалансировано, `over_exposed` — переэкспонировано).
4. **Перцептивное хеширование и цифровые отпечатки**:
   - **Average Hash (aHash)**: 64-битное сравнение средних уровней яркости.
   - **Difference Hash (dHash)**: 64-битное сравнение направлений градиента.
   - **Perceptual Hash (pHash)**: 64-битное хеширование низкочастотной матрицы двумерного дискретного косинусного преобразования (DCT).
   - Устойчивость к изменению масштаба и сжатию с потерями.
5. **Движок поиска дубликатов и схожих изображений**:
   - Потокобезопасный in-memory реестр с защитой мьютексами (`sync.RWMutex`).
   - Сравнение в реальном времени с настраиваемыми порогами расстояния Хэмминга и коэффициента схожести.
6. **Конвейер трансформации и обработки**:
   - Билинейная интерполяция при масштабировании высокого качества.
   - Кадрирование (crop) по прямоугольной области.
   - Преобразование в градации серого и инверсия цветов (RGB).
   - Кодирование в форматы PNG и JPEG с настраиваемым качеством сжатия.
7. **Детекция объектов (Object Detection)**:
   - **Статус: НЕ РЕАЛИЗОВАНО / ЗАПЛАНИРОВАНО**. Текущий релиз сфокусирован исключительно на детерминированном компьютерном зрении (метаданные, цветовая палитра, оценка четкости/размытия, перцептивное хеширование, поиск дубликатов и трансформация). Нейросетевая детекция объектов не реализована в данной версии.

## Архитектура и стек технологий

- **Язык**: Go 1.24+
- **Архитектура**: Clean Architecture / Domain-Driven Design (cmd, internal/domain, internal/analyzer, internal/hasher, internal/duplicates, internal/processor, internal/api)
- **Использование стандартной библиотеки**: Полное отсутствие сторонних внешних рантайм-зависимостей; сервис использует нативные пакеты Go `image`, `image/color`, `image/draw`, `image/jpeg`, `image/png`, `net/http` и `math`.
- **Параллелизм и надежность**: Защищенное потокобезопасное хранилище данных, корректное завершение работы по системным сигналам (`SIGINT`, `SIGTERM`), middleware перехвата и восстановления после паник.

## Требования и конфигурация

### Системные требования
- Go 1.24 или выше
- Git
- Docker (опционально для запуска в контейнере)

### Переменные окружения (`.env`)

| Переменная | По умолчанию | Описание |
| :--- | :--- | :--- |
| `PORT` | `8080` | Порт HTTP сервера |
| `APP_ENV` | `development` | Среда запуска (`development`, `production`, `test`) |
| `MAX_UPLOAD_SIZE_MB` | `20` | Максимальный размер загружаемого файла в мегабайтах |
| `SIMILARITY_THRESHOLD` | `0.85` | Минимальный коэффициент схожести (от 0.0 до 1.0) для дубликатов |
| `HAMMING_DISTANCE_THRESHOLD` | `10` | Максимальная разница бит Хэмминга (от 0 до 64) для кандидатов |
| `READ_TIMEOUT_SECONDS` | `30` | Таймаут чтения запроса HTTP |
| `WRITE_TIMEOUT_SECONDS` | `30` | Таймаут записи ответа HTTP |

## Установка и запуск

### Локальный запуск

```bash
# Клонирование репозитория
git clone https://github.com/afzalbek-dev/image-analysis-service.git
cd image-analysis-service

# Создание конфигурационного файла
cp .env.example .env

# Запуск сервера
go run ./cmd/server
```

Сервис начнет принимать запросы по адресу `http://localhost:8080`.

### Запуск через Docker

```bash
# Сборка Docker-образа
docker build -t image-analysis-service .

# Запуск контейнера
docker run -p 8080:8080 --name image-service image-analysis-service
```

## База данных и сохранение данных

- Текущая версия использует высокоскоростной потокобезопасный реестр отпечатков в оперативной памяти (`sync.RWMutex`), оптимизированный для быстрых проверок и минимальных задержек.
- Для масштабных инсталляций предусмотрена архитектурная интеграция с персистентными хранилищами (PostgreSQL с расширением `pgvector` или Redis bitmap index).

---

## Заметки по безопасности

- **Ограничение размера загрузок**: Жесткий лимит размера входящих запросов через `http.MaxBytesReader` предотвращает атаки исчерпания памяти и zip-бомбы.
- **Безопасное декодирование**: Нативные декодеры Go предотвращают переполнения буфера, характерные для уязвимостей в библиотеках на C (таких как LibTIFF или ImageMagick).
- **Отсутствие секретов в коде**: Полная независимость от статических учетных записей. Все настройки берутся из переменных окружения.
- **Защита от сбоев**: Middleware перехвата паник гарантирует, что непредвиденная ошибка вернет корректный HTTP статус 500, не обрушив весь процесс сервера.

---

## Известные ограничения и планы развития

- **Текущие ограничения**: Детекция объектов **не реализована** в текущем релизе (запланирована для будущей интеграции ONNX runtime); in-memory реестр сбрасывается при перезапуске сервера; видеопотоки требуют предварительного извлечения кадров.
- **План развития**:
  1. Реализация нейросетевой детекции объектов и лиц через ONNX runtime / Go биндинги.
  2. Добавление адаптеров персистентного хранения в Redis и PostgreSQL.
  3. Реализация нативного декодера WebP.
